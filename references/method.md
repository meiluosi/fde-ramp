# 为什么这么做，以及每一步的细节

> 执行入口在 `SKILL.md`；这份文档解释背后的道理，方便你按自己的情况调整。

## 0. 先想清楚：我要的到底是什么

不是「把这个行业的知识都学完」，而是三样东西：

1. **一张能被纠正的结构图**：价值链 + 链上玩家和关系 + 客户的业务域/流程/活动表；
2. **一套能开口的行话**：约 50 个词，知道怎么用、不会和近邻词搞混；
3. **一份待验证清单**：把「我不知道」变成「我知道该问谁、怎么问」。

这三样都指向同一个动作：**尽快让一线员工来纠正你**。所以下面四步不是按「知识量」分的，是按「离被纠正还有多远」分的。

## 1. 第 1 步：为什么先读报告、年报、监管目录

| 材料 | 读它解决什么 | 不读会怎样 |
|---|---|---|
| 券商行业深度报告（2 份近一年 + 1 份老一点的） | 行业结构、玩家、商业模式、关键变量；老报告用来看结构变化 | 不知道行业靠什么赚钱，画出来的链是教科书 |
| 客户年报 / 招股书 / 官网 | 客户自己怎么描述业务、收入构成、战略措辞 | 画的是行业通用图，不是这家客户 |
| 监管文件**目录**（不细读） | 知道有哪些约束、谁在管、哪些是硬门槛 | 说错一句合规话，专业度归零 |

**为什么券商报告通常有用**：它们要回答「这个行业怎么赚钱、谁在赚、变量是什么」，正好是画地图需要的东西。但研报有立场、有滞后，所以只取结构，数据要交叉验证。

**监管目录怎么读**：只读「标题 + 发布机关 + 文号 + 一句话管什么」，不读正文。目的是建一张「监管地图」，知道遇到问题该翻哪份。

### 1.1 全链路关系：从分段到玩家到关系

只画「上游→中游→下游」不够。你要能说出**每一段里谁在、谁大、谁和谁一伙、谁下一步想干什么**。

| 层 | 要回答 | 典型证据 |
|---|---|---|
| 分段 | 这条链分几段？段与段之间交易什么？ | 研报结构章、协会年报、监管目录 |
| 玩家 | 每段有谁？上市/非上市、规模、区块/产能 | 年报、招股书、公司官网、行业新闻 |
| 现状 | 最近一年做了什么？ | 公告、新闻、招标/中标、环评 |
| 规划 | 下一步要做什么？ | 年报/公告=**公司自述**；媒体/研报=**媒体转述**；动作反推=**推断** |
| 关系 | 供应/采购、股权、合资、技术、客户、渠道、竞争、监管 | 公告、工商信息、合作新闻、招标文件 |

画图建议：每段配一句大白话（「这段在干啥」），再画两张 mermaid——一张链路图（从资源到卖气）、一张玩家关系图（谁和谁什么关系）。图给人看，表给核对用。

三条纪律：

1. **规划不是已发生**：写「公司自述：2027 年产能翻倍」，不要写「2027 年产能翻倍」。
2. **关系不猜股权**：没有公开证据的持股/合资一律标 ❓，进待验证清单。
3. **每段都要有玩家**：某段一个玩家都叫不出，说明这段你还没看懂。

## 2. 第 2 步：为什么是 50 个词

- 行业高频词大约 200–500 个，但**决定你是不是外行**的是前 50 个；
- 50 个词刚好能在一张 A4 内看完、通勤路上过一遍；
- 每个词必须配「一句人话 + 一个近邻辨析 + 一个误用示例」，否则只是背定义。

术语的三种典型错误（AI 最容易犯）：

1. **近邻混淆**：把「解吸」和「吸附」、「排采」和「抽采」当成一回事；
2. **时点混淆**：把已经废止/调整的补贴口径、旧标准当成现行；
3. **口径混淆**：同一个词在监管文件、现场、商务口中含义不同（如「利用率」）。

校准的可靠锚是**客户自己的文档**：年报、官网、制度、招标文件、招聘 JD、新闻稿。找不到锚的词，状态必须是「待客户确认」。

### 2.1 从业者内容源：公众号/知乎/B站/播客

研报擅长结构，不擅长「现场怎么叫」。从业者写的科普/实战文章往往更接近真实叫法：

- 公众号：行业观察、企业号、工程师个人号、协会号；
- 知乎：从业者长答、面试题、踩坑记录；
- B站/播客/小宇宙：访谈、复盘、培训课切片；
- 行业论坛/贴吧/公开群文章。

用法与纪律：

1. **只用于候选词与用法例句**，不作为关键数字的唯一来源；
2. 记录**作者/机构/日期**，区分「科普」「厂商软文」「培训广告」；
3. 文章里的数字要回到官方/年报交叉验证；
4. 摘录用一句原话（≤60 字）+ 链接，不整段复制；
5. 从业者说法常有地域/企业差异，标注「某公司/某盆地口径」。

## 3. 第 3 步：为什么先分业务域、再画流程、再拆活动

**直接画流程图，画出来的一定是「行业通用流程」，不是这家客户的。** 正确的颗粒度是三层：

1. **业务域**：一块相对独立、有明确目标和负责人、与其他块有接口的业务。域分对了，流程才有归属；
2. **流程**：每个域 1–2 条主干流程 + 审批/决策链；
3. **环节/活动**：一行一个环节，填「做什么 / 谁做 / 影响谁 / 用什么工具 / 业务背景 / 多久一次或什么触发 / 常见异常与后果 / 上下游交接（含记录）/ 谁验收签字 / 是否外包或自营 / 输入输出」。

为什么活动表最重要：

- 它是**一线员工能逐行纠正**的最小单位——「这一行哪列不对」比「讲讲你们流程」有效得多；
- 「业务背景」列逼你回答「为什么这么做」，这是访谈里最容易拿到隐性知识的地方；
- 工具/系统列会暴露你对数字化的无知，正好拿去被纠正。

流程图的重点仍然是**问号**：一张 100% 准确但含糊的图没人愿意改；一张 70% 准确但标了 8 个具体问号的图，对方会主动帮你改。

## 4. 第 4 步：为什么「被否定」比「被讲解」有用

> 「您能给我讲讲你们的流程吗？」→ 对方给你**标准答案**（对外口径、教科书流程）。
> 「我画了张图，肯定有不对的地方，您帮我改改。」→ 对方给你**真实答案**（哪里特殊、哪里踩过坑、哪里文件没写）。

机制：

- 人纠正错误的动机远强于从零讲解的动机；
- 纠正时对方会顺手说出「为什么」，而「为什么」才是行业 know-how；
- 你交出了一张具体的图，对方能判断你的水平，从而决定跟你说多深。

## 5. 子代理怎么分工（可选，但推荐）

### 第 1 步：3 个 reader + 1 个 chain builder + 1 个 synthesizer

- reader A：读 3 份研报，输出「行业结构 / 玩家 / 商业模式 / 关键变量 / 数据点（带出处）」；
- reader B：读客户年报/官网，输出「客户自述业务 / 收入构成 / 战略措辞 / 与行业的差异」；
- reader C：读监管目录，输出「文件清单 / 管什么 / 硬门槛」；
- chain builder：按分段逐个列玩家，补现状/近一年动作/规划（标自述/转述/推断）与关系（标证据与信心）；
- synthesizer：合并成 `value-chain.md` + `chain.md` + `sources.jsonl`，标出冲突与缺口。

三个 reader 的 prompt 必须一致（除材料不同），避免把「材料差异」误判成「行业差异」。

### 第 2 步：4 个 miner + 1 个 calibrator

- miner A：从研报/年报抽高频名词与缩写；
- miner B：专门找「近邻易混对」；
- miner C：专门找「可能过时/地域化/口径不一」的说法；
- miner D：搜公众号/知乎/B站/播客/论坛的从业者科普，抽候选词与「现场叫法」；
- calibrator：拿客户文档逐词找使用例句，给出「公开说法 / 待客户确认 / 不确定」（「已校准」只给客户/一线确认过的词）。

### 第 3 步：1 个 domain planner + 1 个 flow drafter + 1 个 activity filler + 1 个 red team

- domain planner：先划业务域与域间接口，标出哪些域是推断；
- flow drafter：按域画主干流程 + 审批链，每个节点标信心等级；
- activity filler：把流程拆成活动行，补「谁做/影响谁/工具/业务背景/输入输出」；
- red team：指出「哪些行你其实没有证据，只是行业常识」，把「有依据」降级为「可能过时」或「我猜的」。

### 第 4 步：人（不可替代）

AI 可以准备图、生成问题、整理记录，但不能替代你去被否定。**没有第 4 步的速成不算速成。**

## 5.5 方案模式：算账与找机会

如果目标不只是「能对话」，而是「给客户提 AI 改造方案」，在第 4 步之后加一步：

1. **四个数字**：耗时、日频次、出错率、单次代价；再问「谁做、什么职级」，找 HR/财务要人力单价；
2. **两个成本**：每天人力成本 = 耗时÷60×日频次×人力单价；每天风险成本 = 出错率×日频次×单次代价；两项相加 = 改进上限；
3. **六个 AI 信号**：重复人工判断、信息散在多系统、大量非结构化文档、有标准但靠人记、流程大量等待、有人在偷偷自救；
4. **四维打分**：业务价值、可行性、数据可得性、政治阻力；数据/政治红灯先解决；
5. **第一个项目**：选第一象限里最靠右的（最容易落地），不是最靠上的。

完整方法、问法和算例见 `references/opportunity-analysis.md`；模板是 `templates/process-metrics.md`、`templates/opportunities.md`、`templates/business-case.md`；算账用 `scripts/calc_process.py`。

**核心**：不靠观点，靠客户自己的数字。

## 6. 客户什么都没给时（自学模式）

这很常见，不用等。做法：

1. 先靠公开资料把地图、全链路、业务域、活动表画出来；
2. 所有「这家客户」的判断都标 ❓ / 「待客户确认」，不要写成事实；
3. 术语最高只到「公开说法」，不能标「已校准」；
4. 第一次见面就交底：「我按公开资料画了一版，肯定和你们实际不一样，您帮我改」；
5. 来源清单（`sources.md`）要完整——这是你「有依据」的证明；
6. 自检时，语言/决策维度不要给自己超过 2 分（没有客户文档，没法校准）。

## 7. 资料不够、约不到人时怎么办

| 情形 | 调整 |
|---|---|
| 拿不到客户文档 | 术语全部标「待客户确认」；第 4 步优先问术语，再问流程 |
| 见不到一线员工 | 用客户售后/实施/渠道代替；仍不行就明确说「这次只能到 2 分，不能到 3 分」 |
| 公开资料很少 | 只交「公开源版本 + 待验证清单」，不要假装已经准备好 |
| 只有一天时间 | 1 份研报 + 客户年报 + 监管目录 → 半张地图 + 3 段玩家 + 20 个词 + 3 个域/5 行活动 + 一次短访谈 |
| 只有三天时间 | 第 1 步压缩，第 2/3 步合并，第 4 步留出整天 |

**底线**：如果第 4 步一次都约不到，不要交付「已就绪」的结论，只交付「公开源版本 + 待验证清单」。

## 8. 和「写报告」的区别

| | 写报告 | 本 skill |
|---|---|---|
| 目标 | 产出一份可审计的报告 | 让一个人能对话 |
| 成功标准 | 来源齐全、结论可核验 | 能问出好问题、接住反对、被一线认可 |
| 核心产物 | 报告 / 图谱 / 公司卡 | 图（带问号）+ 全链路关系 + 业务域/活动表 + 术语小抄 + 修正记录 |
| 谁做最后一步 | 模型 | **人**（拿着图去被否定） |

两者不冲突：报告型工具可以作为第 1 步的加速器，但**不能替代第 4 步**。
