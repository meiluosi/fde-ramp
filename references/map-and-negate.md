# 画图与「被否定」现场协议

> 这份文档只解决一件事：**如何用一张具体的、带问号的图，换到一线员工的真实流程与隐性知识。**

## 1. 画图的三个层次

一张合格的速成图，必须同时有三层：

| 层 | 内容 | 作用 |
|---|---|---|
| 主干 | 资源 → 生产 → 集输 → 利用 → 销售 | 让对方知道你的整体理解 |
| 客户特化 | 这家客户实际怎么走、哪些环节外包/自建 | 让对方看到你做了功课 |
| 问号 | 你明确不确定的节点/时序/审批/口径 | 给对方一个低成本的纠正入口 |

**没有第三层的图不要拿出去。** 对方会觉得你在浪费他的时间；有问号的图，对方会觉得你在认真做事。

## 2. 信心标记

| 标记 | 含义 | 处理 |
|---|---|---|
| ✅ | 有来源，且来源是客户/官方/近期 | 可以直接讲 |
| ⚠️ | 有来源，但可能过时/口径不明/来自行业通用而非客户 | 讲的时候加「我理解是……」 |
| ❓ | 猜的，没有直接证据 | 必须进待验证清单，且现场优先问 |

每条 ❓ 必须写成「我猜是 X」，不能写成「这里不清楚」。前者能被一句话纠正，后者只能得到「嗯，挺复杂的」。

## 3. 待验证清单的排序

按 **风险 × 验证成本** 排：

- 风险：错了会不会导致方案/报价/承诺出错（高/中/低）；
- 验证成本：问一个人就能确认 / 要查文件 / 要走流程（低/中/高）。

**先问「高风险 × 低成本」的。** 例如：

| 问题 | 风险 | 成本 | 找谁 |
|---|---|---|---|
| 排采是自营还是外包？ | 高（影响成本模型） | 低 | 站长 |
| 销售是管道还是液化？比例多少？ | 高（影响收入结构） | 低 | 商务 |
| 开发方案谁审批、周期多长？ | 中 | 中 | 技术负责人 |
| 与煤矿的矿权重叠怎么处理？ | 高 | 高 | 政府/矿方 |

## 4. 现场开场：用「帮我改错」，不要用「请给我讲讲」

### ✅ 推荐

> 「我根据公开资料画了一张咱们的业务流程图，肯定有不对的地方，您帮我改改。特别是这几个我画问号的地方——比如这里我猜排采是自营的，这里我猜销售主要走管道，您看错在哪？」

### ❌ 避免

> 「您能给我讲讲咱们的业务流程吗？」
> 「咱们公司是怎么运作的？」
> 「这个行业有什么特点？」

前者给对方一个**具体的纠正任务**，后者给对方一个**开放讲解任务**。人纠正错误的动机远强于从零讲解。

## 5. 现场七条规则

1. **不辩护**。被纠正时说「原来是这样」，不要说「可是研报上说……」。
2. **追问「为什么」**。改完之后问一句「为什么会这样？」——原因才是隐性知识。
3. **记录 before/after**。我原以为 → 实际 → 差异原因 → 影响。
4. **追问边界**。「所有项目都这样，还是分情况？」「以前也这样吗？」
5. **追问文件**。「有没有哪份文件/制度能一锤定音？我能看一下吗？」
6. **追问其他人**。「还有谁会不同意这张图？我应该再找谁聊？」
7. **不录音/不拍照未经同意**；敏感信息（价格、人事、未公开项目）不主动问。

## 6. 记录模板（`verification-list.md`）

```markdown
## 修正 3 · 排采不是自营

- 我原以为：排采由客户自己的队伍完成。
- 实际：主体是自有队伍，但偏远井/低产井外包给第三方。
- 差异原因：自有队伍成本高，低产井外包更划算；且外包队伍按产量结算，有激励。
- 影响：成本模型要分「自营/外包」两段；外包比例是商务谈判变量。
- 来源：2026-10-21 与 XX 站站长访谈；无公开文件。
- 待验证：外包比例、结算方式、合同期限。
```

## 7. 把修正变成「问不出来的信息」

被改的地方，通常属于三类隐性知识：

| 类型 | 例子 | 价值 |
|---|---|---|
| **制度外做法** | 低产井外包、临时用工 | 公开资料永远没有 |
| **历史遗留** | 某个审批环节是历史原因留下的 | 解释「为什么流程这么绕」 |
| **部门博弈** | 两个部门都能管、谁签字看情况 | 决定你的方案该找谁 |

每一条修正，都追问一句：「如果我不知道这个，通常会犯什么错？」——这句话能直接产出方案里的风险清单。

## 8. 访谈后 30 分钟必做

1. 趁记忆新鲜，把 `verification-list.md` 写完；
2. 更新 `business.md`，把被改的节点从 ❓ 改成 ✅（并标「来源：访谈 XX」）；
3. 更新 `glossary.md`，把被纠正的术语改状态、加「误用示例」；
4. 重算一次就绪度，记录分数变化；
5. 把没解决的问题写成下一次访谈的开场问题。

## 8.5 用活动表访谈（v0.2 新增，推荐主用）

把 `business.md` 打出来，比流程图更适合逐行纠正：

> 「我按公开资料和行业常识，把咱们的业务拆成了一张活动表。每一行是我猜的：这个环节做什么、谁做、影响谁、用什么系统、为什么这么做。您帮我看看哪几行不对，特别是标了 ❓ 的。」

规则：

1. **一次只读 5–8 行**，不要整表倒给对方；
2. 每行先读「做什么 → 谁做 → 影响谁 → 工具 → 背景 → 多久一次/什么触发 → 常见异常/后果 → 上下游交接」，再请对方改；
3. 重点问「业务背景」列：「为什么要这么做？」——这一列最容易拿到制度外做法；
4. 被改的行当场标 `✏️`，回来写进 `verification-list.md` 并回填 `business.md`；
5. 工具列如果被纠正（如「我们不用 SCADA，用 XX」），单独记一条——这是数字化切入点的线索。

## 8.6 带链路图去被否定（chain.md）

> 「我把链上玩家和关系画了张图：每段有谁、谁和谁是什么关系、谁明年要干什么。您帮我看看哪些关系是错的、哪些规划是媒体在替他们吹。」

规则：
1. 先问**关系**：「A 和 B 是供应还是合作？有没有股权？」——关系错，后面的判断全错；
2. 再问**规划**：「这条是公司自己说的，还是媒体转述？实际推进到哪一步了？」；
3. 最后问**谁不在图上**：「这条链上还有谁是我漏掉的？」；
4. 被改的关系/规划写进 `verification-list.md`，回填 `chain.md`，并把无证据的边标 ❓。

## 8.7 带域图去被否定（business.md）

> 「我猜咱们的业务分这几块：每块有目标、负责人、上下游接口。您看哪块其实不是一个部门？哪块我漏了？」

规则：
1. 域的名字和边界以客户组织为准，不以公开资料为准；
2. 重点问**接口**：「这块和那块之间谁给谁数据/谁卡谁？」——接口往往是真实痛点；
3. 问**责任**：「这块出问题，最后谁背？」；
4. 被改的域/接口写进 `verification-list.md`，回填 `business.md`。

## 9. 一次访谈怎么安排（30–45 分钟）

| 时间 | 动作 |
|---|---|
| 0–3 min | 说明来意：我在做行业速成，画了张图，想请您帮我改错 |
| 3–10 min | 让对方看主干，听他第一反应（哪里最不对） |
| 10–25 min | 逐条过问号，每条问「我猜是 X，对吗」+「为什么」 |
| 25–35 min | 追问边界、文件、其他人 |
| 35–40 min | 复述你听到的修正，确认没理解错 |
| 40–45 min | 问「下次我该找谁/看什么」 |

## 10. 常见失败

- 带了一张没有问号的图 → 对方不知道从哪改；
- 问「请给我讲讲」→ 得到标准答案；
- 被纠正时辩护 → 对方不再说真话；
- 只记结论不记原因 → 下次还会错；
- 只访谈一个人 → 把个人习惯当成公司流程；
- 回来不改图 → 修正没有变成能力。

## 11. 访谈工具包（按角色）

### 老板 / 业务负责人

- 今年最想改善的一个业务指标是什么？为什么是它？
- 如果只能先改一个环节，您会选哪里？
- 哪些方案您已经看过/否过？为什么？
- 这件事谁拍板、谁出钱、谁会用？
- 什么结果会让您觉得这次试点值得继续？

### 一线 / 班组长

- 您一天里最烦、最重复的动作是什么？
- 这一步平均多久一次？一次多久？最容易错在哪？
- 有没有您自己做的 Excel/话术本/检查清单？能看看吗？
- 出错之后谁收拾？要花多久？
- 如果有个助手帮您做一半，您最希望它先做哪一半？

### IT / 数据

- 这个环节的数据在哪个系统？能不能导出/调 API？
- 数据质量怎么样？有没有唯一 ID 对齐？
- 权限、审计、脱敏有什么要求？
- 如果只做一个旁路试点，最小集成是什么？

### 财务 / 采购

- 这个环节的人力成本怎么算？岗位/职级/外包单价是多少？
- 出错/返工/罚款大概什么量级？
- 预算走谁？采购周期受什么约束？
- 试点费用怎么记？需要什么审批？

### 法务 / 合规

- 哪些数据不能出内网/不能给第三方模型？
- AI 生成内容要不要标识？谁审核？
- 供应商合同里数据使用/知识产权怎么约定？
- 出问题谁承担责任？

## 12. 追问句式（被纠正时）

- 「原来是这样。那为什么会这样？」
- 「如果换成另一种情况，还成立吗？」
- 「有没有哪份文件/系统能一锤定音？」
- 「还有谁会不同意这张图？他会怎么说？」
- 「我下次最容易错在哪？」

## 13. 记录与同意

- 访谈前：说明用途、是否录音、谁能看到；
- 记录格式：原话 → 我的理解 → 修正 → 影响 → 待验证 → 谁负责；
- 匿名化：客户名/人名/金额按需脱敏；
- 访谈后 24 小时内回写 `verification-list.md` / `verification-list.md` / `chain.md`；
- 未经同意不把客户材料贴进公开仓库或外部模型。
