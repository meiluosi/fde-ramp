# 术语卡协议：AI 列候选，客户文档做校准，人做终审

> 目标：约 50 个词，每个词一句人话 + 一个近邻辨析 + 一个误用示例。
> 铁律：**没有客户文档或一线确认的词，状态不许写 `verified`。** 公开源再权威，也只能到 `public`。

## 1. 状态定义

| 状态 | 含义 | 允许出现的场合 |
|---|---|---|
| `verified` | **客户文档或一线员工**确认过这个词的用法，且与你的解释一致 | 可以直接在客户面前使用 |
| `public` | 公开源（官方标准/监管文件/年报/研报/学术）确认定义，但**未用客户文档校准** | 可用于内部准备；客户面前要加「我理解是……」 |
| `needs-customer` | 只有 AI/百科解释，或公开源互相矛盾，或客户具体怎么用不明 | 必须进待验证清单 |
| `unsure` | 你知道自己分不清它和近邻概念 | 必须进待验证清单，且优先问 |

> 为什么把官方标准也放在 `public`：官方文件确认的是「行业定义」，不是「这家客户的口径」。客户现场完全可能用另一个词、另一套单位。**verified 只认客户/一线。** 案例包里没有客户文档，所以一个 `verified` 都不应该有——这是诚实，不是缺陷。
>
> 来源在 `sources.jsonl` 里建议加一个 `sourceKind` 字段：`official / report / practitioner / media / other`，方便区分「研报说的」和「一线博主说的」。

## 2. 候选生成：三个角度，不要一个 prompt 生成完

### Miner A · 高频名词与缩写

从研报、年报、官网、招标文件、招聘 JD 中抽「反复出现且外行看不懂」的名词/缩写。每个词记录：出现次数、首次出现的句子、来源 id。

### Miner B · 近邻易混对

专门找「看起来像但实际不是一回事」的词对。常见类型：

- 同一过程的两端（吸附 vs 解吸）；
- 同一结果的不同口径（产量 vs 利用量 vs 销售量）；
- 不同空间/时序（采空区 vs 采动区 vs 未采动区）；
- 不同主体/方式（井下抽采 vs 地面抽采）；
- 不同环节（提纯 vs 液化 vs 压缩）；
- 行业 vs 监管 vs 现场的不同叫法（煤层气 vs 煤矿瓦斯）。

### Miner C · 可能过时/地域化/口径不一

- 已经调整的补贴标准、废止的标准、旧版分类；
- 只在某省/某企业使用的说法；
- 同一个词在监管文件、现场、商务口中含义不同；
- 缩写歧义（同一缩写在不同语境指不同东西）。

> 三个 miner 各跑一份，取并集；**不要互相看结果**，否则会收敛到同一种错误。

### Miner D · 从业者内容源（公众号/知乎/B站/播客/论坛）

从业者写的科普/实战文章常比研报更接近现场叫法。做法：

1. 搜「行业词 + 科普/入门/避坑/一线/面试」等组合；
2. 记录作者/机构/日期/链接，区分「科普」「厂商软文」「培训广告」；
3. 抽候选词与**原句用法**（≤60 字），标 `sourceKind: practitioner`；
4. 把从业者说法与官方文件/客户文档对照：一致 → 可升 `public`；冲突 → 标 `needs-customer`；
5. 从业者内容不得作为关键数字的唯一来源。

## 3. 校准：用客户文档做锚

对每个候选词，按以下顺序找「它被怎么用」的例句：

1. 客户年报 / 招股书 / 官网 / 新闻稿；
2. 客户制度、流程文件、招标文件、技术协议；
3. 客户招聘 JD（JD 里的用词最接近一线）；
4. 监管文件 / 国家标准 / 行业标准；
5. 行业协会、学术论文；
6. 券商研报（只作参考，不作终审）。

记录格式：

```markdown
| 术语 | 客户文档中的原句（≤60 字） | 文档 | 与你的解释是否一致 | 状态 |
```

找不到客户文档时，不要编一句「客户可能会这么说」。直接标 `needs-customer`，并把「去哪找」写进待验证清单。

## 4. 人终审：8 个必查项

1. **过时**：这个说法现在还成立吗？补贴/标准/分类有没有更新？
2. **同物异名**：客户是不是用另一个词说同一个东西？
3. **同名异物**：这个词在客户那里是不是指另一个东西？
4. **口径**：单位、含税/不含税、标方/方、产量/销量/利用量，是否说清？
5. **地域**：是否只在某省/某盆地/某企业成立？
6. **缩写歧义**：展开后是否唯一？
7. **书面 vs 口语**：这个词是文件用语还是现场口语？在哪个场合用？
8. **近邻辨析**：能不能用一句「A 不是 B，因为……」说清区别？说不清就标 `unsure`。

## 5. 每个词的卡片格式

```markdown
### 解吸 Desorption
- 一句话人话：煤里吸附着的甲烷，因为压力降低而「脱附」出来，变成可采的气。
- 行业怎么用：「解吸压力」「解吸效率」「解吸量」；现场关心的是「什么时候开始解吸、解吸得均不均匀」。
- 最容易混淆：吸附（Adsorption）——吸附是气贴到煤基质上，解吸是它离开；两者是同一过程的正反方向。
- 误用示例：❌「煤层气靠抽采把气从煤里吸出来」——抽采是工程手段，解吸是物理过程，方向说反了。
- 状态：public（待用客户文档校准）
- 来源：S3、S7
```

## 6. 收敛规则：80 → 50

- 先保留 60–80 个候选；
- 删除：客户文档里不出现、且访谈中没人用的低频词；
- 合并：同物异名合并成一条，别名放 `aliases`；
- 保留：所有近邻易混对，哪怕低频——它们决定你是否像内行；
- 最终 50 个词里，`needs-customer` 不应超过 1/3；超过说明资料不足，先补 第 1 步。

## 7. AI 的五种典型错误（终审时逐条对照）

1. **把相近概念混为一谈**：用百科定义拼出一个「看起来对」的解释；
2. **把过时说法当现行**：补贴、标准、分类已经变了；
3. **把行业词解释成字面意思**：如把「排采」解释成「排水+采气」但漏掉「控压」这个核心；
4. **编造缩写**：把不存在的缩写展开得很合理；
5. **口径漂移**：同一张表里「产量」有时指井口量、有时指销售量。

> 终审不是「再看一遍」，是拿这 5 条逐条查。查不出的，标 `needs-customer`，不要猜。

## 8. 术语卡的使用场景

- **见客户前 30 分钟**：过一遍 50 词，重点看 `needs-customer` 和「误用示例」；
- **访谈中**：听到新词立刻记下，回来补卡；
- **访谈后**：被纠正的术语写进 `corrections.md`，并更新状态；
- **方案/汇报写作**：只用 `verified` 的词；`needs-customer` 的词要么不用，要么先确认。
