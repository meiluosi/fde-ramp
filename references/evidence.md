# 证据纪律

> 一句话：**事实带来源，推断标推断，不知道的进清单。**
> 一份材料里出现一个没有来源的关键数字，整份材料的可信度就归零。

## 1. 来源分级

| tier | 类型 | 例子 | 用法 |
|---|---|---|---|
| **A** | 官方一手 | 政府/监管文件、上市公司年报/招股书、公司公告、标准原文 | 可直接作为事实 |
| **B** | 行业机构 / 学术 | 行业协会、统计年鉴、论文、专业咨询公开摘要 | 可作事实，注明机构与年份 |
| **C** | 媒体 / 券商公开摘要 | 新闻报道、研报摘要/图表（非全文） | 作线索，关键数字需 A/B 交叉 |
| **D** | 其他 | 百科、自媒体、论坛、AI 生成内容 | 只能作候选，不作事实 |

**冲突时**：客户文档 > A > B > C > D。冲突本身要记录，不要静默取一个。

## 2. `sources.jsonl` 格式

每行一个 JSON 对象：

```json
{"id":"S01","title":"...","url":"https://...","publisher":"国家能源局","published":"2026-03-01","accessed":"2026-10-18","tier":"A","sourceKind":"official","usedFor":["value-chain","regulators"],"note":"..."}
```

要求：

- `id` 稳定且零填充（S01、S02…），正文引用写 `[S03]`；
- `url` 必须是你**实际打开过**的；
- `accessed` 是访问日期（用会话当天日期）；
- `published` 不确定写 `"unknown"`；
- `tier` 只能 A/B/C/D；
- `sourceKind`（建议填）：`official` / `report` / `practitioner` / `media` / `other`，区分「官方文件」「研报」「从业者科普」「媒体转述」，避免把公众号说法当官方口径。

## 3. 正文引用格式

- 事实：`2025 年煤层气产量约 XX 亿方 [S03]。`
- 推断：`推断：该客户销售以管道气为主（无直接来源，依据是……）。`
- 待验证：`待验证：补贴口径（见 V2）。`
- 过时：`⚠️ 该数字为 2023 年，可能已过时 [S7]。`

## 4. 什么时候必须标「待验证」

- 数字没有 A/B 级来源；
- 同一个指标有两个不同口径；
- 来源超过 12 个月且是动态数据；
- 只有 AI 解释、没有文档原句；
- 客户文档与公开源冲突。

## 5. 陈旧度规则

| 数据类型 | 超过多久标 ⚠️ |
|---|---|
| 政策/补贴/价格 | 12 个月 |
| 产量/装机/玩家份额 | 12 个月 |
| 储量/地质数据 | 24 个月（并注明评估基准日） |
| 法律法规 | 以现行有效版本为准，需查「是否废止」 |
| 流程/组织 | 12 个月（组织调整很常见） |

## 6. 量纲与口径

以下必须在括号里写清，否则算不合格：

- 含税 / 不含税；
- 标方（Nm³）/ 方（m³）；
- 产量 / 销售量 / 利用量；
- 日 / 月 / 年；
- 单井 / 区块 / 公司 / 全国；
- 探明 / 控制 / 预测储量；
- 权益口径 / 作业口径。

## 7. 与 validator 的关系

`scripts/validate_artifacts.py` 目前会检查：

- 必需产物是否存在（含 `.mmd` / `calibration-log.md` / `drill-scorecard.md`）；
- `sources.jsonl` 每行可解析、`id/title/url/published/accessed/tier` 齐全、tier 合法、`accessed` 为 `YYYY-MM-DD`、`usedFor` 为字符串或数组；
- 正文中的 `[S#]` 都能在 sources 中找到（跳过代码块与行内代码）；模板占位符 `{{` 是否残留；
- `glossary.md` 的术语行与状态统计（跳过汇总表）、`verification-list.md` 的已填条目数、`flow.md` 的 ❓ 节点数、`corrections.md` 的已填修正数（这些是 WARN，`--strict` 下变 ERROR）；
- `state.json` 的计数与文件实际是否一致。

`readiness.py` 另外会做**证据闸门**：没有 ≥5 处修正、≥8 条来源、≥20 个术语、≥5 条待验证、≥10 个链路玩家、≥5 条关系、≥3 个业务域、≥10 行活动（目标 15），即使五维自报满分也不会 PASS。

## 7.1 从业者来源规则（公众号/知乎/B站/播客/论坛）

- 只用于**候选词、现场叫法、流程细节**，不作为关键数字的唯一来源；
- 记录作者/机构/日期；区分科普、厂商软文、培训广告；
- 摘一句原话（≤60 字）+ 链接，不整段复制；
- 与官方文件/客户文档冲突时，以客户文档 > 官方文件为准，并记录冲突；
- 平台内容可能被删除/修改，引用时同时保存访问日期。

## 7.2 给人看的来源清单（sources.md）

`sources.jsonl` 是给脚本用的；人看的是 `sources.md`。填完 `sources.jsonl` 后运行：

```bash
python3 scripts/render_sources.py --root ramp
```

它会列出编号、标题、发布方、日期、等级、类型、用途、链接。每个产物的正文用 `[S01]` 引用，文末或附录指向 `sources.md`——这样别人能查你说的每句话从哪来。

## 8. 三条红线

1. **不编造来源**：宁可写「未找到公开源」，也不要造一个看起来合理的 URL/文号。
2. **不把推断写成事实**：推断必须能被识别出来。
3. **不隐藏冲突**：两个来源矛盾时，把矛盾写出来，交给人判断。
